# 블루 아카이브 공식 홈페이지 레퍼런스 리뷰

## 조사 범위

- 대상: https://bluearchive.nexon.com/home
- Firefox에서 실제 라이브 페이지 확인: 데스크톱 1440×1000, 모바일 UA/390×844.
- 홈, 상단 메뉴의 호버 드롭다운, 학생명부 화면 전환, 모바일 첫 화면과 스크롤을 확인했다.
- 라이브 접속이 가능해 제공된 `블루 아카이브.html`은 대체 자료로 사용하지 않았다.
- 아래의 **관찰**과 **MOLU 적용 제안**은 구분한다. 배너 내용과 사이트 설정은 이후 변경될 수 있다.
- 이번 작업은 리뷰 문서 작성이며, MOLU 화면이나 동작은 변경하지 않았다.

## 1. 핵심 인상

공식 사이트의 중심은 **밝은 학원·일상 배경 위에 게임 UI를 올린 로비**다.
단순히 흰색과 청록색을 쓰는 SF 대시보드가 아니다. 교실, 바다, 햇빛, 학생 일러스트가 감정을 만들고, 패널과 버튼은 그 위에서 필요한 역할을 한다.

MOLU는 이미 청백색과 밀레니엄 단말기 표현이 있다. 공식에 더 가까워지려면 장식을 더 늘리기보다 **생활감 있는 배경, 이미지 비중, 글자 위계**를 바꾸는 편이 효과적이다.

## 2. 실제 관찰

| 항목 | 공식 사이트에서 확인한 특징 | 디자인상 역할 |
| --- | --- | --- |
| 배경 | 교실과 바다가 이어지는 전체 배경, 무음 반복 영상 | 페이지를 하나의 장소처럼 느끼게 한다 |
| 헤더 | 흰 바탕, 로고·주 메뉴, 오른쪽 로그인·소셜·BGM 버튼 | 복잡한 장면 속에서 조작 위치를 고정한다 |
| 홈 배치 | 왼쪽 이벤트 바로가기, 중앙 쪽 이미지 배너, 오른쪽 소셜 피드 | 콘텐츠 성격별로 영역을 나누고 배경이 보일 공간을 남긴다 |
| 패널 | 가는 밝은 테두리, 투명한 바탕, 소셜 글은 불투명한 흰 카드 | 배경과 연결감을 유지하면서 읽을 부분은 분리한다 |
| 색상 | 흰색·연한 하늘색·중간 파랑 중심. 남색은 강조나 대화창 오버레이에 사용 | 차가운 실험실보다는 청량한 학원물 인상을 만든다 |
| 이미지 | 이벤트 배너·학생·교실이 분위기의 상당 부분을 담당 | CSS 도형만으로는 같은 인상을 내기 어렵다 |
| 사물 모티프 | 집무실 바로가기는 노트와 펜, 학생명부는 학교별 책 | 기능을 세계관 안의 사물로 설명한다 |
| 문구 | 학생명부에 안내 캐릭터와 선생님에게 말을 거는 대화창 | 메뉴 이동도 게임 속 행동처럼 느끼게 한다 |
| 이동 | 메뉴 호버 시 연한 하늘색 드롭다운, 화면 전환 시 로고 연출 | 게임과 연결된 일관된 경험을 만든다 |

### 확인한 수치와 서체

관찰 환경에서의 값이며, 그대로 복사해야 할 규격은 아니다.

- 데스크톱 상단바: 86px, 흰 배경.
- 주 메뉴: `GmarketSansMedium`, 18px. 이벤트 링크: `Pretendard`, 16px.
- 이벤트 바로가기: 높이 80px, 반경 5px, 흰색 20% 테두리와 5% 배경.
- 스타일에 반복적으로 등장하는 색: `#FFFFFF`, `#99D1FA`, `#336CA5`, `#00365C`, `#0C98ED`.
- 홈 배너: Swiper 사용. 확인 시점 설정은 전환 300ms, 자동 넘김 3초, 반복 재생.
- 데스크톱과 모바일에서 서로 다른 가로·세로 배경 영상 URL을 사용한다.

### 모바일

데스크톱을 단순히 축소하지 않는다.

- 메뉴를 햄버거 버튼으로 접고 헤더를 줄인다.
- 세로 배경 구도로 인물과 장면을 다시 잡는다.
- 주요 배너를 화면 하단 쪽으로 옮겨 가로 넘김으로 제공한다.
- 데스크톱의 여러 콘텐츠 열을 같은 폭 안에 계속 유지하지 않는다.
- 문서 바깥이 아닌 내부 컨테이너가 스크롤되는 구성이 관찰됐다. 이 구현 방식까지 MOLU가 따라갈 필요는 없다.

## 3. 현재 MOLU와의 차이

| 현재 MOLU | 공식 레퍼런스의 방향 |
| --- | --- |
| 관측소·연구실 단말기 | 선생님이 머무는 교실·게임 로비 |
| 회로, 좌표, 작은 영문·등폭 라벨 | 배경 장면, 학생, 노트와 책 같은 사물 |
| 청록 포인트와 정돈된 데이터 패널 | 하늘색과 중간 파랑, 풍부한 이미지 |
| 정보 구조가 주인공 | 장면이 분위기를 만들고 정보 UI가 올라감 |

현재 디자인이 잘못됐다는 뜻은 아니다. 밀레니엄이라는 목표에는 맞는 부분이 있다. 다만 **공식 홈페이지에 가까운 인상을 원한다면 청록색만 바꾸거나 캐릭터 하나를 추가하는 것으로는 부족하다.**

추천 컨셉은 **“샬레 교실에서 보는 밀레니엄 일정 보드”**다. 기존 단말기 정체성을 버리지 않고 공식 사이트의 밝은 장소감과 사물 표현을 보탠다.

## 4. MOLU 적용 제안

### A. 배경은 분위기, 달력은 정보

- 권리 문제가 없는 밝은 교실·하늘 계열 배경을 헤더 주변과 바깥 여백에 사용한다.
- 달력 본체는 흰색 또는 거의 불투명한 바탕을 유지한다.
- 날짜 칸 아래로 움직이는 배경이나 인물 무늬가 비치게 하지 않는다.
- 처음에는 정지 이미지 한 장이면 충분하다. 동영상은 그다음 선택 사항이다.

### B. 이미 있는 구조를 살린다

현재의 **달력 + 오늘의 브리핑**, 이벤트 캐러셀, 필터, 상세 모달을 유지한다.
공식 홈의 좌측 이벤트 목록·중앙 배너·우측 소셜 피드를 그대로 옮기면 정작 달력이 좁아진다.

```text
[ MOLU       캘린더 · 목록                         가져오기 ]

[ 낮은 높이의 교실/하늘 배경 + 주요 이벤트 배너          ]

[ 이번 달 · 오늘 · 카테고리 필터                         ]
[                                  ][ 오늘의 일정     ]
[         넓고 불투명한 달력        ][ 시작/종료 시각  ]
[                                  ][ 가까운 일정     ]

[ 선택형 캐릭터 / 조작을 가리지 않는 하단 영역           ]
```

모바일에서는 배경 소개 영역을 짧게 하고 월·날짜·오늘 일정이 먼저 보이도록 한다. 큰 배너가 첫 화면을 모두 차지하는 공식 홈의 우선순위까지 따라가지는 않는다.

### C. ‘수첩·명부’ 표현을 작은 곳에 넣는다

- 오늘의 브리핑은 선생님의 메모 카드처럼 표현할 수 있다.
- 카테고리는 색이 있는 인덱스 탭처럼 표현할 수 있다.
- 제목 일부에 작은 리본이나 서류 탭을 쓰되 모든 카드에 반복하지 않는다.
- 회로와 좌표 표시는 주인공이 아니라 가장자리 장식으로 줄인다.
- 작은 영어 라벨은 줄이고 날짜·제목·시간의 크기 차이를 더 분명하게 한다.

### D. 색과 글자

- 화면 바깥은 밝은 하늘색, 본문 패널은 흰색, 중요한 선택 상태는 중간 파랑을 중심으로 정리한다.
- 현재의 청록은 밀레니엄 보조색으로 남길 수 있다.
- 제목은 넓고 친근한 서체/굵기로, 날짜와 일정명은 명확한 크기로 표현한다.
- 공식의 Gmarket Sans를 검토할 수 있지만 꼭 새 폰트를 추가할 필요는 없다. 현재 Noto Sans KR을 유지하고 위계만 바꿔도 개선된다.
- 등폭 서체는 시간·ID 같은 실제 데이터에 제한한다.
- 분류색은 의미를 유지하고, 색만으로 분류를 구분하지 않는다.

### E. 움직임은 이미 있는 것을 재사용한다

- MOLU의 기존 배너 전환은 320ms로 공식의 확인된 300ms와 이미 비슷하다.
- 자동 넘김은 기존 6초와 일시정지 기능을 유지하는 편이 일정 읽기에 더 적합하다.
- 기존 터치 효과는 작게 유지한다. Swiper로 갈아타거나 새로운 애니메이션 라이브러리를 추가할 이유는 없다.
- 구라는 렌더링 테스트용 선택 기능으로 유지한다. 실제 서비스 캐릭터는 디자인 방향과 이용조건에 맞는 자산을 별도로 준비한다.
- 배경 영상·3D 캐릭터·여러 자동 배너를 동시에 계속 움직이게 만들지 않는다.

## 5. 그대로 가져오지 않을 것

1. **전체 화면 로딩 연출:** 일정 확인을 기다리게 할 이유가 없다.
2. **본문 전체의 투명 패널:** 날짜와 작은 시각의 대비를 해친다.
3. **큰 홍보 배너 우선 배치:** 일정 서비스는 날짜와 다가오는 일정이 먼저다.
4. **여러 영역의 별도 스크롤:** 달력 탐색과 모바일 사용을 복잡하게 만든다.
5. **외부 소셜 피드 임베드:** 현재 요구사항에 없고 외부 서비스 로딩에 의존한다.
6. **배경 영상·자동 BGM·3D의 동시 상시 실행:** 읽기 집중도와 기기 자원을 고려해야 한다. 실제 성능 수치는 이번 리뷰에서 측정하지 않았다.
7. **공식 자산의 무단 배포:** 디자인 참고와 이미지·영상·로고·모델 재사용 권리는 별개다.

## 6. 추천 적용 순서

1. **배경과 색상:** 밝은 장소감을 만들되 달력의 흰 바탕은 유지.
2. **타이포그래피와 장식 정리:** 작은 기술 라벨을 줄이고 한글 제목·날짜를 강조.
3. **브리핑/필터의 수첩 모티프:** 기존 DOM과 기능을 최대한 활용.
4. **이벤트 비주얼:** 사용할 수 있는 이미지가 있을 때 도입. 없으면 기존 텍스트 배너 유지.
5. **선택형 캐릭터·배경 모션:** 앞 단계가 완성된 뒤 성능과 접근성을 확인하며 추가.

새 배너 이미지 필드를 도입한다면 JSON v1의 엄격한 검증 계약을 별도로 검토해야 한다. 단순 테마 변경 때문에 일정 데이터 형식부터 바꾸지 않는다.

## 결론

**공식 홈페이지의 ‘화면 구성’을 복사하기보다 ‘밝은 장소 + 게임 속 사물 + 읽기 쉬운 UI’라는 표현 방식을 가져오는 것이 MOLU에 맞다.**

달력 기능을 다시 만들 필요는 없다. 배경·타이포그래피·카드 표현을 바꾸는 것이 우선이며, 더 많은 효과나 의존성을 추가하는 것이 우선은 아니다.
